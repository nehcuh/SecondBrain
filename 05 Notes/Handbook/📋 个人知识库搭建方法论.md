# 📋 个人知识库搭建方法论

> 基于 SecondBrain v2 实践总结。从理念到落地，从人到 AI 协作。

---

## 一、核心理念：先设计接口，再填充内容

大多数人搭知识库的做法是：开 Obsidian → 建几个文件夹 → 开始写笔记 → 写多了就乱。

我们的做法反过来了：**先定义「卡片协议」，再让内容遵守协议**。

为什么？因为协议是 AI 能读懂的接口。你的知识库最终不只有你自己在用——未来的 Agent Crew 需要知道：这个文件是什么类型？状态是什么？跟什么东西关联？

**三个核心决策：**

| 决策 | 我们的选择 | 为什么 |
|------|-----------|--------|
| 元数据标准 | 所有卡片必须含 `type` 字段 | AI 不需要猜文件用途 |
| 就地组织 | 靠 frontmatter 关联，不靠文件夹层级 | 同一内容可跨维度被检索 |
| 模板驱动 | 每种卡片有独立模板 + QuickAdd 入口 | 创建零摩擦，格式零偏差 |

## 二、目录设计：编号即意图

```
01 Goals/      ← 你想成为什么
02 Areas/      ← 你持续精进什么
03 Projects/   ← 你要交付什么
05 Notes/      ← 你学到了什么
06 Tasks/      ← 你要做什么
07 Habits/     ← 你每天坚持什么
99 Templates/  ← 以上所有卡片的模具
```

**原则：**
- 编号锚定优先级。01-03 是战略层，05-07 是执行层，99 是工具层
- 资料库用 `_assets/` 前缀，跟内容文件夹一眼区分
- 按年/月/周分层组织高频率内容（任务、会议、剪藏），防止单目录堆积成山

**反例：** 不要建 `08 Archive/`、`09 Contacts/` 这种单独编号——既然能用 `archived: true` 和 `subtype: contact` 标记，何必多一个顶级目录？

## 三、卡片类型设计：给每个东西一张身份证

11 种原子卡片，每种都有明确的 `type` + `subtype` + 专属模板：

| 卡片 | type | 关键属性 | 生命周期 |
|------|------|----------|----------|
| 年度目标 | `goal` | year, progress | active → completed |
| 季度目标 | `goal` | quarter, parent, KR | active → completed |
| 领域 | `area` | parent, description | active → archived |
| 项目 | `project` | deadline, area, milestones | planning → active → done |
| 主题 | `topic` | area, 章节列表 | active → done |
| 任务 | `task` | status, priority, due | todo → done |
| 习惯 | `habit` | frequency, checkins | 持续打卡 |
| 会议 | `meeting` | date, attendees, 行动项 | 会后 → 追踪 |
| 联系人 | `contact` | org, role, email | 持续更新 |
| 学习笔记 | `note` | status: reading→refined→absorbed | 渐进式六层 |
| 灵感 | `note` | status: spark→developing→live→planned | 火花 → 孵化 → 试运行 → 项目 |

**设计信条：**
- 每种卡片只存它该存的信息，不多不少
- 全类型可选 `icon` 字段（单个内容相关 emoji，勿用类型标记）：AI 分诊时填、手填亦可，外部引用以「icon 标题」形式展示
- 习惯打卡可证据化：`evidence: true` 的习惯打卡时补 `checkin_notes` 注记（这次做了/看了什么），checkins 有日期而无注记 = 待补注——防「打勾即做完」的自欺
- 关联靠 `area`、`goal`、`parent`、``[[wikilink]]``，不靠文件夹
- 状态流转清晰——任何时间点都能知道这个卡片「现在是什么状态」

## 四、渐进式阅读六层

不是「读完写个总结」就完了。六层结构倒逼深度思考：

```
📋 原文摘录   → 保存关键段落，标记来源
🤖 AI 摘要    → 模型一句话总结（标注模型）
🎯 核心提炼   → 用自己的话重组，去水留干
💭 我的思考   → 连接已有知识，表达不同意见
✅ 行动项     → 读完要干什么
🔗 关联       → 上游/下游笔记的链接
```

如果只做前两层，那是「收藏」不是「学习」。做到第六层，知识才真正变成你的。

## 五、Dashboard 设计：注意力流水线

不是炫酷的仪表盘，而是按心理节奏排列的行动中枢：

```
打开 Dashboard →
  📊 统计卡         ← 0.5秒，大局观
  📥 Inbox          ← 有什么要处理？
  ☑️ 今日任务       ← 今天必须干什么？
  🤝 今日会议       ← 今天要开什么会？
  🔄 今日习惯       ← 今天要打卡什么？
  ───── 行动就绪 ─────
  💡 灵感火花       ← 脑子里冒出了什么？
  📓 学习主题       ← 在学什么？
  📝 最近笔记       ← 最近写了什么？
  ───── 回顾就绪 ─────
  ✅ 今日完成       ← 今天干完了什么？
  🚀 项目           ← 项目进度如何？
  📂 领域           ← 领域全貌
  ⚠️ 逾期 / 📅 近7天 / 🎯 目标
```

**原则：先紧急后重要，先执行后规划，先今天后历史。**

## 六、AI 就绪设计

旧知识库的问题是：结构是人读的，AI 读不懂。

新知识库的核心区别：**标准化元数据 = AI 的 API**。

| 传统做法 | AI 就绪做法 |
|----------|-------------|
| 文件夹分类 | `type` + `subtype` 字段 |
| 手动写摘要 | `## 🤖 AI 摘要` 段落 |
| 靠记忆找关联 | Agent 读 `area`/`goal` 字段自动发现 |
| Inbox 手动清理 | Agent 扫描 `status: inbox` 提醒处理 |
| 灵感烂在备忘录 | `status: spark` → 孵化追踪 → Dashboard 可见 |

**四个 Agent 角色（未来）：**
- 会议 Agent: 检测新会议 → 提取行动项 → 建任务
- 每日 Agent: 扫 Vault → 生成 Effort 简报
- 关联 Agent: 监听新笔记 → 匹配同领域 → 建议链接
- 目标 Agent: 季度末 → 对照 KR → 自动复盘

## 八、起步三步走

如果你要复刻这套系统：

**第一步：建模板（30分钟）**
1. 定义你的卡片类型（我们用了 11 种，你可以从 4-5 种开始）
2. 每种写一个模板，含 frontmatter 骨架
3. 配好 QuickAdd 入口，Cmd+P 能一秒创建

**第二步：建 Dashboard（30分钟）**
1. 从统计卡 + 今日任务 + 习惯打卡开始
2. 逐步加领域、项目、灵感
3. 不需要一次做全——缺啥加啥

**第三步：开始用（持续）**
1. Inbox 清零是每日底线
2. 会议后立刻填行动项
3. 灵感来了 5 秒内 Cmd+P 捕获

## 九、踩坑实录

这些是我们今天踩过的，留给你避雷：

| 坑 | 根因 | 解法 |
|----|------|------|
| 日历插件日记建到根目录 | `dailyNoteFolder` 没配 | 3 个配置文件都得改 |
| Dataview `contains()` 报错 | DQL 函数不能用在 JS 箭头函数里 | JS 里用 `.some()` |
| `date` 字段比较失败 | DateTime vs string | 统一 `.toFormat("yyyy-MM-dd")` |
| QuickAdd JSON 逗号缺失 | 手工编辑 JSON 漏了逗号 | 用 Python 脚本改，别手工拼 |
| Templater 双份配置 | `templater.json` + `data.json` 两个文件 | 两份都得改 |
| `Templates` 目录反复复活 | 只改了插件配置没改根配置 | 查引用用 `grep -rn` 全扫 |
| Chrome Clipper `replace` 炸 | `|replace` 过滤器不被支持 | 用纯变量，不加过滤器 |
| Dashboard 并排布局歪 | Dataview `dv.el()` 自带容器包裹 | 用 `dv.container.createEl()` 内联样式 |

## 十、一句话总结

**好的知识库不是你写了多少笔记，而是你的笔记能否回答「这是什么、什么状态、跟什么相关」这三个问题——让人和 AI 都能回答的那种。**
